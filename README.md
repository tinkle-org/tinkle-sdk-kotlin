# Tinkle SDK for Android

Kotlin bindings and prebuilt Android libraries for the shared [Tinkle Rust
engine](https://github.com/tinklehq/libtinkle). Apache-2.0; see [LICENSE](LICENSE).

## Install

Add JitPack to your settings repositories:

```kotlin
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven("https://jitpack.io") {
            content { includeGroup("com.github.tinklehq") }
        }
    }
}
```

Then use the SDK repository's released tag:

```kotlin
dependencies {
    implementation("com.github.tinklehq:tinkle-sdk-kotlin:<tag>")
}
```

The single public Maven component is the root Android library. Its POM and Gradle
metadata carry **JNA 5.18.1 as an AAR**, Kotlin stdlib, and **coroutines 1.10.2**
transitively. JNA's bundled `libjnidispatch.so` is part of the 16 KB runtime
contract; do not replace it with an older JNA release or the desktop JAR.

Requirements: Android **minSdk 24**, consumer compileSdk **36**. The library
compiles against API 36; the **host application sets its own targetSdk**, and
the included consumer targets **36**. The ABI matrix is `arm64-v8a`,
`armeabi-v7a`, `x86_64`, and `x86`.

## Initialize

```kotlin
import com.tinkle.sdk.TinkleSdk

// Application.onCreate(), before any generated com.tinkle.sdk API calls:
TinkleSdk.initialize()
```

Initialization is thread-safe and idempotent. It explicitly calls
`uniffiEnsureInitialized()` before `tinkleFfiInit()`. This is required with
UniFFI **0.32.2** to check the loaded native library's contract and function
checksums; generated single-crate Kotlin bindings do not do so automatically.
Generated objects should be closed/destroyed when their owner finishes.

The engine owns protocol handling, RPC correlation, subscriptions, cursor
semantics, and reconnect behavior. A platform app supplies an asynchronous
`FfiCursorStore` adapter over its durable store. This package adds no duplicate
persistence engine and contains no application UI. The in-memory Rust store is
for ephemeral sessions/testing. Source-build adapters should also use the same
`tinkle-ffi` engine, rather than copying protocol or persistence logic.

## Artifact-only distribution

JitPack runs **JDK 17**, **Gradle 8.13**, **AGP 8.13.0**, and **Kotlin 2.3.0**.
It never installs Rust, builds Rust, or generates bindings. The wrapper JAR is
from Gradle's official `v8.13.0` GitHub tag, SHA256
`81a82aaea5abcc8ff68b3dfcb58b3c3c429378efd98e7433460610fecd7ae45f`.
`gradle-wrapper.properties` pins the official distribution SHA256 too.

Core release promotion copies two files into this repository together:

* `sdk-artifact.json`: the complete schema-1 release manifest, with version,
  exact source SHA, `source_repository: "tinklehq/libtinkle"`,
  `source_tag: "tinkle-ffi-v<version>"`, and the four `ios`, `swift_bindings`,
  `android`, and `kotlin_bindings` artifact entries (`filename`, `url`, `sha256`).
* `src/main/kotlin/com/tinkle/sdk/tinkle_ffi.kt`: generated by that same release's
  locked UniFFI 0.32.2 generator.

There is no fabricated initial release manifest or generated binding. Before the
first release, artifact-dependent tasks fail clearly unless given explicit local
bootstrap inputs. The handwritten Gradle project and initialization adapter can
be reviewed independently of release promotion.

`prepareSdkArtifacts` verifies canonical HTTPS GitHub URLs for the exact source
repository/tag/filename, restricts redirects to GitHub release hosts, and verifies
SHA256 before reading ZIPs. Extraction rejects traversal, Windows/absolute paths,
duplicate/unexpected entries, missing ABIs, and oversized archives. Entries are
materialized as regular files in a disposable task directory; no ZIP entry can
overwrite repository sources. The Kotlin ZIP must match the committed generated
file byte-for-byte. Only verified native output is copied to
`build/generated/sdk/jniLibs/<abi>/libtinkle_ffi.so`. All four ABIs are mandatory.
Published AARs also retain the manifest at `assets/tinkle-sdk/sdk-artifact.json`.

No credentials or Maven Central publication setup are needed. `jitpack.yml`
runs verification followed by `publishToMavenLocal`, using the standard
`maven-publish` release component. SDK tags can be `v<version>` or `<version>`;
the manifest version must agree. Committing the manifest and generated binding
from different releases is an error.

## Local bootstrap and source packaging

In the Rust repository, install Rust **1.99.1** and NDK LTS **r30
(`30.0.16248370`)** with all four Rust Android targets. Configure `ANDROID_HOME`
or `ANDROID_NDK_HOME`; no machine paths are checked in. The producer checks NDK
metadata against API 24 and uses the API-24 Clang drivers.
The [r30 platform metadata](https://android.googlesource.com/platform/ndk/+/refs/tags/ndk-r30/meta/platforms.json)
declares a minimum of **21** and maximum of **37**, so API 24 is within range.

```sh
# From libtinkle, after generating/checking bindings:
bash scripts/build-android.sh
# Optional: SDK_OUTPUT_DIR=/absolute/output/path bash scripts/build-android.sh
```

The producer builds `tinkle-ffi` / `tinkle_ffi` with
`cargo rustc --locked --profile android-release --target <target> --crate-type cdylib -p tinkle-ffi --lib`
from the workspace root, removing inherited Rust flags so the checked-in build-ID
and 64-bit 16 KB linker flags apply. It checks bindings against each unstripped
library before stripping. Outputs in `target/sdk` (or `SDK_OUTPUT_DIR`) are:

* `android-native-libraries.zip`: exactly `jniLibs/<abi>/libtinkle_ffi.so`.
* `kotlin-bindings.zip`: `com/tinkle/sdk/tinkle_ffi.kt` rooted in the ZIP.
* `android-native-debug-symbols.zip`: separate per-ABI `.so.dbg` files.
* `android-build-metadata.json`: build IDs, SHA256s, byte counts, targets, API,
  NDK, source revision, version, and profile. Debug and shipped IDs must match.

Explicit developer subsets use `--abis x86_64`, are forbidden in CI/release
mode, and produce `*-dev.zip` native artifacts so they cannot be promoted as a
complete release. A release invocation always builds all four ABIs.

Copy the actual generated Kotlin file into this repository's source path (the
core promotion/bootstrap helper does this). For manifest-free local validation,
provide the directory containing both ZIPs and their hashes:

```sh
./gradlew verifySdkArtifacts :assembleRelease \
  -PsdkArtifactDir=/absolute/path/to/libtinkle/target/sdk \
  -PsdkAndroidSha256=<android-zip-sha256> \
  -PsdkKotlinBindingsSha256=<kotlin-zip-sha256>
```

Environment equivalents are `TINKLE_SDK_ARTIFACT_DIR`,
`TINKLE_SDK_ANDROID_SHA256`, and `TINKLE_SDK_KOTLIN_BINDINGS_SHA256`.
Core CI also supports `TINKLE_SDK_NATIVE_ARCHIVE` (absolute path, canonical native
ZIP filename) plus `TINKLE_SDK_NATIVE_SHA256`; the sibling Kotlin ZIP is compared
against the staged binding. With a committed manifest, its hashes remain
authoritative for both local and remote archives. Manifest-free publication is
restricted to `0.0.0-local`. JitPack requires committed release metadata.

## Verification

```sh
# Build-time archive/URL/checksum rejection tests; no Android/native runtime.
./gradlew -p buildSrc test

# Default consumer path uses the published AAR + POM + Gradle metadata.
./gradlew publishReleasePublicationToSmokeRepository
./gradlew :sample:connectedDebugAndroidTest

# Test exact candidate AAR bytes, as core CI does:
./gradlew :sample:connectedDebugAndroidTest \
  -PtinkleSdkTestAar=/absolute/path/to/tinkle-sdk-kotlin-release.aar

# Full installed release/R8 + all bundled ELF + APK ZIP alignment proof:
bash scripts/verify-consumer.sh --core /absolute/path/to/libtinkle \
  --aar /absolute/path/to/tinkle-sdk-kotlin-release.aar --page-size 16384
# Repeat on a regular-page device with --page-size 4096.
```

Bootstrap artifact properties/environment must remain set during producer tasks.
The `sample` app is included only for explicit `:sample:*` tasks or
`-PincludeSample=true`; it has no publication. Both smoke variants enable R8
optimization/obfuscation and use local debug signing; the `debug` smoke variant
is deliberately non-debuggable. `-PsmokeBuildType=release` selects
`connectedReleaseAndroidTest` for the release variant. The normal consumer path
resolves Maven metadata; the file-AAR CI adapter explicitly supplies JNA and
coroutines because a standalone AAR has no dependency metadata.

The installed smoke calls both initializers, constructs/destroys the real Rust
in-memory store, then connects the packaged Rust client to a test-only loopback
gateway. Subscription recovery invokes a suspending **Kotlin** cursor store
from **Rust**, and the returned cursor travels through the wire response back
to Kotlin. The native call sites and callbacks live in the minified target APK.
Consumer rules preserve JNA native methods, reflected structures and callbacks.

Run runtime lanes on API 36 with regular 4 KB and 16 KB images, plus API 24
minimum-OS proof where available. The 16 KB check must turn compatibility mode
off and verify the property read-back; a backcompat-assisted load is not proof.
`verify-android.sh` checks every 64-bit `LOAD` segment and build ID, including
JNA's `.so` in the final APK. `zipalign -c -P 16 -v 4` checks final package
alignment. An AAR assembly or unit-test pass alone proves no installed runtime
behavior. Record unavailable runtime lanes explicitly.
